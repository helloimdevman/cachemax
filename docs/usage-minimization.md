# 유지 요청 사용량 축소 — 2026-09-25

유지 문구를 `Only ".". No tools.`에서 `Only .`로 줄였습니다. 원래 모델과 세션을
사용하고, 도구 차단은 기존 호스트 가드가 담당합니다. 응답은 계속 `.`이어야 하며
다른 응답·도구 시도에는 기존 중지 규칙이 적용됩니다.

**확인된 개선은 매회 추가되는 입력의 감소입니다. 거의 무료인 유지까지 달성한
것은 아닙니다.** 재개 후 실제 3분 주기에서 세 플랫폼의 유지 9회가 모두 완료됐고,
그중 짧은 문구 6회가 모두 `.`로 응답했습니다. 세 플랫폼 모두 최초 문자열 회상과
실시간·기록 조회의 유지 메시지 숨김을 통과했습니다. 예정 시각 대비 로컬 시작
지연은 1.39~5.77ms였습니다. 주기는 계속 직전 요청 완료 후 3분입니다.

| 플랫폼 | 확인된 토큰 변화 | 해석 범위 |
| --- | --- | --- |
| Codex | 연속 요청의 전체 입력 증가량 17 → 13토큰, −4토큰 | 증가량 23.5% 감소이며 전체 입력·비용의 23.5% 절감이 아님. 출력은 모두 5토큰 |
| Grok | 입력 증가량에서 직전 출력량을 뺀 값 27 → 23토큰, −4토큰 | 보정값 14.8% 감소. 짧은 문구 두 번 모두 23으로 관측. 원시 증가량에는 직전 보고 출력도 반영됨 |
| Claude | 마지막 짧은 요청의 새 캐시 쓰기 33토큰, 출력 3토큰 | 기존 문구 요청에서 추가 문맥이 함께 바뀌어 문구 단독 절감량은 분리하지 못함 |

Grok의 보정값은 `현재 전체 입력 − 직전 전체 입력 − 직전 보고 출력`입니다.
문구만을 별도 토크나이저로 센 값은 아니며 다른 새 문맥도 포함할 수 있습니다.
Codex의 재개 첫 요청에는 1,281토큰이 추가돼 안정 구간 비교에서 제외하고 원자료에
그대로 남겼습니다. 뒤의 기존·짧은 요청에서 17·13이 나왔으며, 별도 2초 진단의
17·13 차이도 일치했습니다.

| 재개 후 유지 요청 비용, CLI 추정치 | 짧은 문구 1 | 기존 문구 | 짧은 문구 2 |
| --- | ---: | ---: | ---: |
| Claude | $0.012733 | $0.017441 | $0.011715 |
| Codex | 미제공 | 미제공 | 미제공 |
| Grok | $0.009557 | $0.037882 | $0.009558 |

이 비용 차이를 문구의 인과 효과로 보지 않습니다. Claude의 새 캐시 쓰기는 순서대로
184·768·33토큰으로 다른 문맥 변화가 섞였고, Grok의 중간 요청만 캐시 읽기가 0이었습니다.
캐시 읽기는 여전히 요청당 수만 토큰입니다. Claude의 마지막 요청을 시간당 20회로
단순 환산해도 약 $0.234이며, Grok의 적중 요청도 같은 환산에서 약 $0.191입니다.
실제 시간당 측정이나 구독 청구액이 아니고, 미적중이 생기면 더 커질 수 있습니다.

원자료·단계별 실패·계산·소스 해시는
[측정 자료](usage-minimization-measurements.json)에 저장했습니다. 이번 작업에서
완료한 대화 요청은 총 39회이고, 제공자 전송 전 로컬 검사 거부 3회는 별도입니다.
전체 진단·검증의 CLI 추정치 합계는 Claude $1.250893, Grok $0.256172이며
Codex 비용은 미제공입니다. 자동 검사 33개가 통과했고 모든 실험 실행기를 종료했습니다.

처음부터 큰 비용 감소를 가정하지 않았습니다. 기존 관측에서 가장 큰 비용은 짧은
출력이 아니라 기존 문맥의 캐시 쓰기와 읽기였습니다. 먼저 18회 진단 요청으로
프로세스 수명, 추론 설정, 문구 길이를 각각 조사했습니다.

| 진단 | 실측 | 결정 |
| --- | --- | --- |
| Claude, 재실행과 상주 프로세스 | 각 4회 요청. 두 경로 모두 뒤쪽 2회에서 새 캐시 쓰기 39토큰 | 상주 구조로 바꿀 비용 근거가 없어 적용하지 않음 |
| Grok, 기존 문구로 high → low → low → high | 출력 22 → 19 → 15 → 31토큰. 두 설정 전환 요청에서 캐시 읽기 0 | 출력 감소보다 큰 미적중 비용이 관측되어 유지 요청별 추론 전환을 적용하지 않음 |
| Codex, 기존 → 짧은 문구 → 기존 → 짧은 문구 | 모든 응답 `.`; 출력 5토큰. 입력 증가량 13 → 17 → 13토큰 | 매회 추가 문맥을 줄이는 짧은 문구를 채택 |

Claude 진단은 양쪽 모두 같은 1,500행 자료와 `--max-turns 1`을 사용한 별도
비교입니다. 이전 12분 관측과 실행 시점·유휴 간격이 달라, 이전 약 $0.348에서
이번 약 $0.011로 낮아진 것을 코드 수정의 효과로 계산하지 않았습니다. 이번에는
수정 전 방식에서도 작은 새 쓰기가 관측됐습니다.

Grok은 로컬 모델 목록에서 `grok-4.7`의 최소 지원 추론 설정이 `low`임을 확인했습니다.
공식 [추론 문서](https://docs.x.ai/developers/model-capabilities/text/reasoning)도 해당 모델의
추론을 끌 수 없다고 설명합니다. 작은 표본에서 추론 설정 전환과 미적중이 함께
나타났지만, 서버 내부 원인을 확정한 것은 아닙니다.

Claude 공식 [캐시 설명](https://code.claude.com/docs/en/prompt-caching)에 따르면 요청마다
전체 문맥을 보내며 앞부분의 일치 여부에 따라 캐시를 읽습니다. 따라서 문구 축소는
추가되는 입력을 줄여도 이미 긴 대화를 읽는 비용을 없애지는 않습니다.

3분 주기 확인의 첫 시도는 플랫폼별 준비·예열 2회와 기존 문구 유지 1회 후
중단됐습니다. `.codex/config.toml`의 수정 시각이 바뀌어 기존 환경 검사가 다음
호출을 제공자에게 보내기 전에 거부했습니다. 당시 내용 해시가 없어 실제 설정
내용도 바뀌었는지는 판단하지 못합니다. 완료된 대화 요청 9회와 로컬 거부 3회를
성공한 실험으로 바꾸거나 제거하지 않았습니다.

환경 검사는 파일 내용의 SHA-256을 비교하도록 수정했습니다. 준비 비용을 다시
쓰지 않도록 같은 합성 세션을 재개해 실제 3분 간격으로 짧은 문구 → 기존 → 짧은
문구를 보내고 마지막에 최초 문자열을 회상하도록 했습니다. 이 단계의 상한은
플랫폼별 4회, 총 12회입니다. 모든 단계를 합친 대화 요청 상한은 39회입니다.
자동 재시도는 없으며 중단과 재개 단계는 별도 자료로 남깁니다.

재개 직후 첫 요청은 긴 공백과 재초기화의 영향을 받을 수 있습니다. 이후의 연속
요청과 구분하며, 이 순차 관측을 독립 표본이나 광범위한 절감률로 해석하지 않습니다.

```sh
# 호스트별 최대 7회. 같은 세션에서 문구만 비교하며 기존 파일을 덮어쓰지 않습니다.
node tests/maintenance-usage.mjs --confirm-usage --host codex --model gpt-6-astra \
  --interval 3m --label fresh-short-run
```

위 명령은 새로운 세션에서 기존 → 짧은 문구 → 짧은 문구 → 기존 순서를 검증합니다.
Claude는 `--host claude --model 'claude-opus-5-5[1m]'`, Grok은
`--host grok --model grok-4.7`로 실행합니다. 모델·설정·런타임 지문이 바뀌면
실험은 실패로 기록하며 자동 재시도하지 않습니다. 정상 응답, 예정 호출, 완료,
대화 회상, 유지 메시지 숨김을 모두 확인합니다. 중단한 합성 세션만 재사용하려면
호스트별 `{ home, cwd, sessionId }`를 담은 로컬 JSON을 `--resume-state`에 전달합니다.
그 경로는 새 준비 요청을 보내지 않고 짧은 문구 → 기존 → 짧은 문구 → 회상,
최대 4회만 실행합니다. 공개 자료에는 이 로컬 경로나 세션 ID를 포함하지 않았습니다.
